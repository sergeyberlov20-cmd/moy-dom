# «Мой Дом» — как устроен сайт и всё, что вокруг него

Документ описывает текущее состояние проекта: статический сайт, серверную часть (Cloudflare),
Telegram-бота, панель заявок и автоматизацию. Обновлено: 18 ноября 2026.

---

## 1. Общая схема

```
Посетитель ──► dom-mc.ru (GitHub Pages: только статика)
                   │  html/css/js, картинки, данные каталога
                   │
                   ├─ форма заявки / квиз / запись на просмотр
                   ▼
        Cloudflare Worker «moydom-leads»
        (API + Telegram-бот + кроны)
                   │
                   ├─ D1 (SQLite): заявки, события, пользователи бота
                   ├─ KV: сессии, коды входа, приглашения, состояния диалогов
                   ├─ GitHub API: коммиты объектов, постов, отзывов
                   └─ Telegram Bot API: уведомления, меню, диалоги
```

- **Сайт** — статика в репозитории `sergeyberlov20-cmd/moy-dom`, ветка `main`, публикуется GitHub Pages
  на домен **dom-mc.ru** (файл `CNAME`). Сборка Pages — 1–2 минуты после коммита.
- **Сервер** — один Cloudflare Worker `moydom-leads`, живущий на
  `moydom-leads.sergeyberlov20.workers.dev`. Домен сайта он не трогает и не проксирует.
- **Данные** — каталог объектов и отзывы лежат файлами в репозитории (`js/data.json`, `js/reviews.js`),
  заявки и статистика — в D1, сессии/коды/состояния — в KV.
- **Бот** — @MoyDom_Mariupol_bot, вебхук на воркер.

## 4. Правило приватности адресов (важно)

- В карточках и на страницах — **только город, район и улица**, без номера дома и участка.
- На карте **нет метки объекта**: показывается район (масштаб ~2 км) и подпись
  «Точный адрес и показ — по телефону».
- Координаты в данных округлены до 3 знаков (~100 м).
- Очистка адреса — `js/address.js` (`window.publicAddress`) на сайте и такая же функция в воркере при добавлении объекта.
- Правило расписано в `docs/address-policy.md`; его нужно соблюдать во всех новых блоках.

## 6. SEO и индексация

- У каждой страницы свой `title`, `description`, `canonical`, Open Graph.
- JSON-LD: статьи — `Article` + `BreadcrumbList`; отзывы — `Organization` + `AggregateRating` + `Review`;
  объекты — `RealEstateListing` + `Offer` + `BreadcrumbList`.
- `sitemap.xml` — 83 адреса, включая все объекты.
- IndexNow: ключ в корне (`9f2a7c1e…txt`), воркер пингует Яндекс/Bing при создании, изменении цены и снятии объекта.
- Старые ссылки `object.html?id=N` работают, но `canonical` ведёт на `/objects/N.html` — дублей нет.
- 404 для старых адресов (`404.html`), `robots.txt`, страницы подтверждения Google/Яндекс.

### Маршруты API

| Маршрут | Назначение |
|---|---|
| `POST /api/lead`, `POST /api/event` | заявка и событие аналитики |
| `POST /api/tg/webhook` | вебхук Telegram |
| `GET /api/tg/setup`, `/test`, `/diag`, `/profile` | вебхук, тест, диагностика, имя/описание/меню команд |
| `GET /api/diag/gh` | проверка токена (`&write=1` — с пробной записью) |
| `POST /api/invite/session` | обмен кода приглашения на сессию панели |
| `GET /api/reviews/update`, `/dry` | обновить/проверить отзывы |
| `GET /api/post/release` | снять `noindex` у вышедших постов |
| `/api/admin/*` | вход/выход, заявки, статус, статистика, пользователи бота, CSV |

Служебные ручки требуют `key=<WEBHOOK_SECRET>`; панель — `Authorization: Bearer <сессия>`.

### Кроны

| Расписание | Что делает |
|---|---|
| `0 6 * * *` (09:00 МСК) | утренняя сводка + публикация отложенных постов |
| `*/15 * * * *` | напоминания о заявках старше 30 минут |
| `0 4 1,15 * *` (07:00 МСК) | обновление отзывов с Яндекс.Карт |


### Хранилища

**D1 (`moydom`)**:
- `leads` — заявки: имя, телефон, сообщение, страница, реферер, UTM, хеш IP, статус, заметка, `reminded_at`;
- `events` — события: `pageview`, `tel_click`, `form_open`, `form_submit`, `object_open`;
- `bot_users` — пользователи бота: имя, username, сообщений/команд, доступ, первый и последний визит.

**KV**:
- `otp:<код>` — код входа в панель (5 минут);
- `sess:<токен>` — сессии панели (30 дней, включая выданные по приглашению);
- `invite:<код>` — приглашения (24 часа, одноразовые);
- `add:<uid>` / `post:<uid>` — состояние диалогов бота;
- `admins:extra` — владельцы, добавленные из бота;
- `msgs:<chat>` — id сообщений чата для «Сброса» (48 часов).

## 8. Путь заявки

1. Форма на `contacts.html`, квиз `/podbor/` или «Записаться на просмотр» на карточке → `mdSendLead()`.
2. `POST /api/lead`: honeypot, формат телефона, лимит 1 заявка / 60 сек с IP.
3. Запись в D1, событие `form_submit`.
4. `tgNotify` — уведомление всем владельцам с кнопками «📞 В работе» / «✅ Готово».
5. Заявка в панели: статусы, заметки, фильтры, CSV.
6. «Новая» дольше 30 минут → напоминание в Telegram (однократно).

## 9. Панель заявок

- Вход: «Получить код» → код в Telegram → ввод → сессия 30 дней.
- Вход по ссылке: `/admin/join.html?c=КОД` — сама обменивает код на сессию и открывает панель.
- Внутри: заявки с фильтрами и статусами, экспорт CSV, сводка (заявки, просмотры, клики, топ страниц,
  **источники заявок по UTM/рефереру**), блок «👥 Пользуются ботом».

## 10. Telegram-бот

Меню внизу: **📋 Заявки · 📊 Статистика · ➕ Добавить объект · ✍️ Написать в блог · 🔗 Пригласить · 👥 Люди · ♻️ Сброс · 🌐 Открыть сайт**.

| Команда | Что делает |
|---|---|
| `/start`, `/help` | приветствие + меню |
| `/leads`, `/leads new` | заявки одним сообщением (до 8, с кнопками статусов) |
| `/stats` | сводка за 7 дней: заявки, звонки, люди в боте, топ страниц |
| `/add` | объект: тип → сделка → название → цена → адрес → комнаты → **описание** → фото |
| `/post` | пост в блог: заголовок → текст → фото → дата (можно будущую) |
| `/price 52 4300000` | смена цены (пересобирает страницу объекта) |
| `/sold 52` | снять объект (удаляет страницу) |
| `/invite` | одноразовая ссылка: сразу панель (24 часа) |
| `/botstats` | кто пользуется ботом (только владелец) |
| `/reviews` | обновить отзывы с Карт (только владелец) |
| `/admins`, `/adduser ID`, `/deluser ID` | управление доступом |
| `/reset` | удалить сообщения чата и показать только приветствие с меню |
| `/id`, `/done 12`, `/cancel` | ID, закрыть заявку, отменить диалог |

Поведение:
- **Шаги диалога удаляются** — в чате виден только текущий шаг; после публикации остаётся один итог.
- **«Сброс» чистит чат** (свои сообщения и ваши команды, в пределах 48 часов) и оставляет приветствие с меню.
- Быстрый ввод одной строкой: `Название | Цена | Адрес | Комнаты Площадь`; для поста — `Текст | 2026-12-01`.
- Доступ: владелец из `ADMIN_IDS` + приглашённые (`/invite`, `/adduser`).

## 11. Отзывы с Яндекс.Карт

- Источник: публичная карточка `yandex.ru/maps/org/moy_dom/98286514548`.
- Воркер забирает HTML, вытаскивает JSON отзывов (57 шт., с ответами организации), сохраняет в `js/reviews.js`
  и обновляет JSON-LD на `/reviews/`.
- Автообновление — 1 и 15 числа в 07:00 МСК; вручную — `/reviews` в боте или `/api/reviews/update?key=…`.
- Если ничего не изменилось — коммита не делает.

## 12. Деплой и обслуживание

**Сайт**: изменить файлы → `git add -A; git commit; git push` → GitHub Pages обновит dom-mc.ru за 1–2 минуты.
После правок CSS/JS нужно поднять версию кэша в `js/sw.js` (`const VERSION = 'vNNN'`).

**Воркер**:
```powershell
cd C:\Users\nice\Desktop\moy-dom-repo\worker
powershell -ExecutionPolicy Bypass -File .\deploy.ps1
```
Скрипт загружает секреты из `.dev.vars` и деплоит. Проверка токена GitHub — `.\check-token.ps1`.

**Проверки после изменений**:
- `…/api/tg/diag?key=…` — бот и вебхук;
- `…/api/diag/gh?key=…&write=1` — права на запись в репозиторий;
- `…/api/reviews/dry?key=…` — доступность отзывов.

## 13. Ограничения и важные детали

- **GitHub Pages** — только статика, сборка 1–2 минуты; серверные вещи — только в воркере.
- **Адреса** — без номеров домов и участков, карта без метки (см. §4 и `docs/address-policy.md`).
- **Telegram** — бот может удалять свои и входящие сообщения только за последние 48 часов; старую историю не видит.
- **Кэш** — после правок статики поднимать `VERSION` в `sw.js`, иначе у посетителей останется старая версия.
- **Отзывы** — если Яндекс начнёт отдавать капчу, обновление вернёт ошибку, данные не портятся.
- **Секреты** — только в `worker/.dev.vars` (в git исключён) и в Cloudflare Secrets.
